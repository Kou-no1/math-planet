# けいさんのほし「くくっち」仕様書

## 現在有効な仕様（Phase 16）

- ホームは星選択。たしざん・ひきざん・かけざん・わりざんの4星を公開する。
- たしざん6エリア、ひきざん6エリア、わりざん3エリアと九九・高学年を、既存の解答・報酬システムで扱う。
- 正答は整数・既存の円周率文字列・商とあまりの構造化値。あまりは割る数未満でなければ正答にしない。
- カスタム装備は全星共通。入手元分類は静的定義の `origin` に保持する。
- Phase 16の学習記録・復習・設定・世界観の仕様は末尾の25.33節を正とする。
- SaveDataはv15。旧記録は演算を推測せず保持し、JSON読み込みにも同じ移行処理を適用する。
- GitHub Pages用のHashRouterと `base: '/math-planet/'` を維持する。
- 本文のPhase 1〜B4は開発履歴を含む。矛盾がある場合はこの現行仕様と新しいフェーズの確定仕様を優先する。

以下は初期MVPからの仕様・開発履歴です。

あなたは、子ども向け教育WEBアプリの設計・実装・テストを担当する、シニアフルスタックエンジニア兼UI/UXデザイナーです。

# 1. プロダクトの目的

## メインターゲット

- 主な対象は小学1〜3年生、8歳以下
- タブレット、スマートフォン、PCで利用
- 文字が十分に読めない子どもでも操作できる
- 1回30秒〜3分程度で遊べる
- 繰り返し遊びたくなる
- 掛け算が苦手な子どもを責めない
- 他人との競争より、過去の自分からの成長を重視する

## 高学年向け追加ターゲット

小学5・6年生および中学受験を目指す児童向けに、発展計算モードも実装します。

# 2. 開発方針

## 技術構成

既存プロジェクトに明確な構成がなければ、以下を採用してください。

- React
- TypeScript
- Vite
- CSS Modulesまたは通常のCSS
- React Router
- localStorage
- Vitest
- React Testing Library
- ESLint
- Prettier

外部UIライブラリは、必要性が高い場合を除いて使用しないでください。

初期バージョンではバックエンドを使用せず、すべての進捗をlocalStorageへ保存してください。

ただし、将来的にFirebaseまたはSupabaseへ移行しやすいように、保存処理はRepositoryまたはService層へ分離してください。

## ルーティングと公開環境

- GitHub Pagesへ公開可能な構成にしてください。
- React Routerは必ず **HashRouter** を使用してください。BrowserRouterはGitHub Pagesでリロード時や直リンク時に404になるため、使用しないでください。
- Viteの `base` は `/リポジトリ名/` に設定してください（実際のリポジトリ名に合わせること）。

## 対応環境

- Chrome
- Edge
- Safari
- iPad
- Androidタブレット
- スマートフォン
- PC

児童1人1台の学校端末（GIGAスクール端末）と、家庭の端末の両方での利用を想定します。

## ドキュメントとコミット運用

- この指示書は `docs/SPEC.md` として保存し、仕様判断に迷ったら参照してください。
- 各Phase完了時に `npm run lint` / `npm run test` / `npm run build` をすべて成功させ、Phase番号を含むコミットメッセージで git commit してください。

# 3. デザインコンセプト

- 明るい

- ゲーム感がある
- 大きなボタン

- キーボード操作にも対応する

- 390px

- 最初は卵から始まる
- 問題に正解すると経験値とコインを獲得する

CSS、絵文字、SVG、簡単な図形などを使い、あとから正式なキャラクター画像へ差し替えられる構造にしてください。

# 6. ゲームモード

## 6.1 おぼえるモード

掛け算をまだ覚えていない子ども向けです。

### 学習段階

1. 見る
2. 聞く
3. まねして読む
4. 答えを選ぶ
5. 自分で答える

### 音声の実装方法

- 「聞く」はWeb Speech API（speechSynthesis）による読み上げを使用してください。日本語ボイスが利用できない端末では、読み仮名のテキスト表示にフォールバックし、段階として成立させてください。
- 「まねして読む」は音声認識を使いません。読み仮名を表示し、子どもが声に出して読んだら「よめた！」ボタンを押す自己申告式にしてください。SpeechRecognition APIおよびマイクは使用禁止です。

### 表示例

`3 × 4`

と同時に、3個ずつのまとまりが4組あることを視覚表示してください。

例：

```text
●●●
●●●
●●●
●●●
```

以下の切り替えを用意してください。

- まとまり表示
- 数直線表示
- たし算表示
- 九九の読み方
- 答えを隠す

### 出題方式

- 段ごと
- 順番
- 逆順
- ランダム
- 4択
- 答え入力
- 式を選ぶ逆問題

## 6.2 スピードモード

以下を実装してください。

- 30秒チャレンジ
- 60秒チャレンジ
- 10問タイムアタック
- 20問タイムアタック
- ノーミスチャレンジ
- 段限定チャレンジ
- 全九九チャレンジ

### スコア計算

基本仕様：

- 正解1問：100点
- 回答速度ボーナス：最大50点
- 5コンボごとにボーナス倍率上昇
- 誤答時はコンボ解除
- ノーミスの場合は最終スコアにボーナス
- むやみに高速連打しても得をしない設計

問題表示から400ms未満で押された回答は、速度ボーナスの対象外にしてください（高速連打対策）。

## 6.3 ランダムゲームモード

最低3種類のミニゲームを実装してください。

### A. モンスターバトル

- 正解すると攻撃
- 連続正解で必殺技ゲージ上昇
- 不正解でも即敗北にしない
- 10問程度で終了
- 最後に宝箱を獲得

### B. 宝箱チャレンジ

- 3問正解すると鍵を1本獲得
- 鍵を集めて宝箱を開ける
- 宝箱からコインまたはアイテムを獲得

### C. ロケットチャレンジ

- 正解すると燃料がたまる
- 回答速度と正確さで到達地点が変わる
- 月、火星、木星などを目指す

ゲームロジックと見た目を分離し、あとから別のゲームを追加しやすくしてください。

## 6.4 にがてモンスターモード

間違えた式を「にがてモンスター」として登録してください。回答に時間がかかっただけの正解は、子どもに見える「にがて」ラベルには登録しません。

回答時間は裏方の出題優先度や習熟度4→5判定には使います。

例：

- 7×8モンスター
- 6×7モンスター
- 8×9モンスター

### 克服条件

- 合計3回正解する
- そのうち1回は登録日と別の日に正解する
- 回答速度は克服条件に含めない

克服するとモンスターが仲間になり、図鑑へ登録されます。

一度の連続正解だけで完全習得とは判定しないでください。

## 6.5 ボスバトル

各段を習得したあとに解放してください。

例：

- 1・2の段ボス
- 3の段ボス
- 4の段ボス
- 全九九ボス

1の段は難度が低いため、独立ボスにせず2の段ボスに統合してください。

ボス戦は10〜15問で構成してください。

不正解でも最初からやり直しにせず、ヒントや再挑戦の機会を与えてください。

# 10. デイリーミッション

毎日3つ表示してください。

例：

- 10問正解しよう
- 7の段を5問解こう
- 5コンボを達成しよう
- スピードモードを1回遊ぼう
- 苦手モンスターに3回勝とう
- 昨日の自分を超えよう

「昨日の自分を超えよう」は、前日のスピードモード自己ベストスコアを上回る、または前日より平均回答時間を短縮することを達成条件としてください。前日の記録がない場合は、このミッションを出題しないでください。

ミッション内容は、プレイヤーの習熟度に応じて変えてください。

日付判定は端末のローカル日付を使用してください。

日付変更時に新しいミッションを生成してください。

# 11. 習熟度判定

問題ごとに学習状態を保存してください。

以下を参考に型を設計してください。

```ts
type MultiplicationFactProgress = {
  id: string
  left: number
  right: number
  correctCount: number
  incorrectCount: number
  consecutiveCorrect: number
  averageResponseTimeMs: number
  bestResponseTimeMs: number | null
  lastAnsweredAt: string | null
  nextReviewAt: string | null
  masteryLevel: 0 | 1 | 2 | 3 | 4 | 5
  recentResults: AnswerResult[]
}
```

習熟度：

- 0：未挑戦
- 1：練習中
- 2：少しできる
- 3：だいたいできる
- 4：定着
- 5：完全マスター

## 判定要素

- 正答率
- 連続正解数
- 回答速度
- 異なる日に正解しているか
- 最近の回答結果
- 最終回答日

単純な累計正解数だけで完全習得としないでください。

# 12. 復習スケジュール

簡易的な間隔反復を実装してください。

基本間隔：

- 翌日
- 3日後
- 7日後
- 14日後
- 30日後

正解が続けば間隔を伸ばし、不正解なら短くしてください。

復習期限を過ぎた問題は、通常問題やデイリーミッションへ適度に混ぜてください。

問題の出題優先度は、おおむね以下の順にしてください。

1. 最近間違えた問題
2. 復習期限を迎えた問題
3. 回答が遅い問題
4. 正答率が低い問題
5. 未挑戦問題
6. 習得済み問題

完全ランダム出題も別設定として残してください。

# 17. 問題生成

問題生成は再利用可能な純粋関数を中心に実装してください。

必要なカテゴリ：

```ts
type QuestionCategory =
  | 'multiplication-basic'
  | 'multiplication-square'
  | 'pi-multiplication'
  | 'two-digit-times-one-digit'
  | 'two-digit-times-two-digit'
  | 'divisors'
  | 'multiples'
  | 'prime'
  | 'gcd'
  | 'lcm'
```

7章の発展計算カテゴリを網羅できるよう、必要に応じてカテゴリを追加してください。

平方数の逆問題は、独立カテゴリにせず `multiplication-square` カテゴリ内で `metadata`（例：`direction: "forward" | "inverse"`）として表現してください。

問題の共通型を設計してください。

例：

```ts
type Question = {
  id: string
  category: QuestionCategory
  prompt: string
  answer: number | string
  choices?: Array<number | string>
  explanation?: string
  difficulty: number
  metadata?: Record<string, unknown>
}
```

4択の誤答候補は、正答と重複しないようにしてください。

誤答候補は、完全な乱数ではなく、子どもが間違えやすい近い値も含めてください。

例：

`7×8`の選択肢に、54、56、63、64などを適切に混ぜます。

## 九九の読み仮名データ

- 九九81件（1×1〜9×9）の読み仮名を `src/data/kukuReadings.ts` に定数データとして定義してください。
- 例：1×1「いんいちが いち」、2×3「にさんが ろく」、2×5「にご じゅう」、7×7「しちしち しじゅうく」、8×8「はっぱ ろくじゅうし」、9×9「くく はちじゅういち」
- 積が1桁のときは「が」が入り、2桁のときは入らない、といった慣用的な読み方に従ってください。
- テストで「81件すべて定義されていること」「ひらがな（と空白）のみで構成されていること」を検証してください。
- 読み仮名の正誤そのものは人間が最終確認します。完了報告でこのファイルのレビューを依頼してください。

# 25.1 Phase 7 追加仕様

## ボスコレクション

- ボスはデータ定義で管理し、1・2の段ボスから9の段ボス、全九九ボス、平方数ボス、円周率ボスを用意する。
- 低学年向けボスはボスバトル画面に配置し、高学年ボスはスーパー計算モード内に配置する。
- 段ボスは該当段で累計20問以上正解すると解放する。全九九ボスは段ボス8体クリアで解放する。
- 高学年ボスは該当カテゴリで累計20問以上正解すると解放する。
- 累計正解数で未解放のボスには、シルエットの下に `あと {n}もん で かいほう！` を表示する。残問数は必要正解数20から現在の累計正解数を引き、0以下にはしない。解放済みボスと全九九ボスには表示しない。
- 難易度はノーマル、ハード、さいそくの3段階とし、下位クリアで上位を解放する。
- ハードは1問6秒、さいそくは1問3秒の制限時間を設け、残り時間はバーと秒数の両方で表示する。
- 不正解や時間切れは即敗北にせず、ダメージなし、コンボ解除、「おしい」「もういちど」の文言で再挑戦できるようにする。
- 各ボスと難易度の初回クリア報酬は固定アイテム1個と固定称号1個にする。ランダムドロップ、ガチャ、射幸性のある演出は禁止する。
- 2回目以降のクリア報酬はコインのみとする。
- 図鑑にはボスとボス限定おたからの全スロットをNo.付きで表示し、未入手はシルエットと「？？？」で表示する。

## 九九の読み仮名

- 九九の読み仮名は `question` と `answer` に分割して保存する。
- 出題中は答え部分を「？」で伏せ、正解後または読み練習時に全文表示する。
- 読み仮名表示は式の上にルビ風に配置し、小さくしすぎない。
- 読み上げ設定がONの場合、正解後に全文を読み上げる。マイクは使用しない。

## 初回チュートリアル

- 初回設定後、最初にホームへ入ったタイミングで3〜5ページのチュートリアルを表示する。
- 各ページは短いメッセージ、絵文字または簡単な図、大きな「つぎへ」ボタン、「スキップ」ボタンを持つ。
- 表示済みフラグをセーブデータに保存し、2回目以降は自動表示しない。
- ホームまたは設定画面から「あそびかた」として再表示できる。

- 九九81問に `factDifficulty(a, b)` で★1〜★5の難易度を割り当てる。
- 重みは `2,5=1`、`3,4=2`、`6,9=3`、`7,8=4` とし、×1を含む問題は★1にする。
- raw重み合計は `2,3=>★2`、`4,5=>★3`、`6=>★4`、`7,8=>★5` に変換する。
- ★1は17問、★5は12問になることをテストで保証する。
- 難易度データは `src/data/` に置き、教師や運用者の判断で後から調整できるようにする。
- 6・7・8の段は誤答が増えやすい最難クラスタとして扱う。特に7・8を含む組合せは経験的にもつまずきやすいため、★5寄りに重み付けする。

## 経験値と出題フィルタ

- 正解時の経験値は `Question.difficulty` に比例させる。平均difficultyが約3になるため、係数は旧1問8XPに近い `8/3` を基準にする。
- 試行ボーナス、モードボーナス、コイン獲得の上限・逓減ルールは既存仕様を維持する。
- 問題生成は `minDifficulty` を受け取り、ボスはノーマル★1以上、ハード・さいそく★2以上、げきムズ★3以上、ミニゲームは★2以上を基本にする。
- minDifficultyで出題候補が空になる場合は、空にならないところまで自動で緩和する。

## スピードモードの段選択

- スピードモードは入室直後に開始せず、共通スタート画面を表示する。
- スタート画面には段選択チップ1〜9、ぜんぶ切替、30秒/60秒選択、スタートボタン、3・2・1カウントダウンを置く。

- 選択した段の `×1〜×9` を出題対象に含める。
- 各段チップには平均difficultyの★を表示し、難しい段には「けいけんちアップ！」の動機付けを表示する。

## 宝箱アイテム

- 宝箱アイテムは `src/data/treasureItems.ts` に20種定義する。
- テーマは、ほし系、うちゅう系、きらきら系、いきもの系、おかし系の5分類とする。
- レアリティは★1ノーマル、★2レア、★3スーパーレア、★4ウルトラレアで表す。
- 各テーマは★1〜★4を1個ずつ持ち、全体で5テーマ×4レア=20種、各レア5種にそろえる。
- ほし系は、ちびほしチップ★1、ほしのベル★2、あまのがわほし★3、ほしのおうかん★4。
- うちゅう系は、ろけっとねじ★1、すいせいびん★2、リングわくせい★3、ぎんがちず★4。
- 宝箱の中身決定は純粋関数にし、乱数はシード可能にする。
- 宝箱は色と説明でレアリティ帯を事前に示す。ハズレは作らない。
- 宝箱を開けるときは、その宝箱のレア範囲内の未所持アイテムを優先して抽選する。
- 未所持候補が残っている間は同じアイテムを出さず、候補が空のときだけ箱別の固定コインへ変換する。
- 全20種を集めた後は、すべての宝箱が固定コイン報酬になる。図鑑のコレクション入手率は100%表示になる。

## 鍵と宝箱のデザイン体系

- 鍵は `src/data/keys.ts` に5種定義する。どうのカギ、きんのカギ、だいやのカギ、にじいろカギ、ほしのカギ。
- 各鍵は対応する宝箱を1種類開けられる。
- 宝箱は、どう、きん、だいや、にじ、ほしの5種類とし、それぞれ★帯と枯渇時コインをデータで持つ。
- レア範囲は階段状にする。どう=★1、きん=★1〜2、だいや=★2〜3、にじ=★3〜4、ほし=★4。
- 枯渇時コインは、どう20、きん40、だいや70、にじ110、ほし160を初期値とする。
- 鍵と宝箱アイテムは専用SVGコンポーネントで描画する。
- SVGはベース形、色、装飾レイヤーを合成する。レアリティが高いほど装飾点や枠が増える。
- レアリティは色だけでなく★数でも表示する。

## セーブデータ

- SaveDataはv6とし、v5以前から `ownedTreasureItems` と `treasureKeys` を補完する。
- 宝箱アイテムは入手ID、入手日、入手方法を保存する。
- 鍵は種類ごとの入手数と初回入手日を保存する。

# 25.24 Phase B1 たしざんの星 playable core

## 星マップ

- ホーム画面に `けいさんのほし` の星マップを置く。

## たしざん6エリア

- たしざんのエリア定義は `src/data/planets.ts` の `additionAreas` に置く。
- `GeneratorSpec` はエリアごとに `operation: 'addition'`、`areaId`、`rule`、`category`、最小/最大の加数を持つ。
- エリアは次の6つとする。
  - `1〜9のたしざん`: `a,b` は1〜8、`a+b <= 9`。答え9以下の入門エリアとして先頭に置く。
  - `10までのたしざん`: `a,b` は1〜9、`a+b <= 10`。
  - `くりあがりのたしざん`: `a,b` は1〜9、`a+b >= 11`。
  - `2けたのたしざん`: `a,b` は10〜99、一の位と十の位がどちらも繰り上がらない。
  - `2けたのたしざん（くりあがり）`: `a,b` は10〜99、一の位の和が10以上。
  - `大きいかずのたしざん`: `a,b` は100〜999。
- くりあがりのたしざんは後続フェーズでボスを強くできるよう、独立エリアとして維持する。

## 問題生成と4択

- たしざん問題生成は `src/game-engine/questions/addition.ts` に置く。
- 問題IDは `add:{areaId}:{left}+{right}` とし、九九の `leftxright` と混ざらないようにする。
- たしざんのB1入力方式は4択に統一する。
- ダミー選択肢は、繰り上がり忘れ、`+10/-10`、`+1/-1`、数字の入れ替えなど、近い誤答から作る。
- `おぼえる` 画面の問題表示、正誤判定、フィードバック、次問題、結果遷移は既存の `LearnPage`、`AnswerControls`、`isCorrectAnswer`、`buildSessionSummary` を流用する。

## 報酬・がっこうモード・にがて

- 正解時のコイン・EXPは既存の `buildSessionSummary` と `applySessionResult` で付与する。
- がっこうモード2の報酬テーパリングは、たしざんIDも `progress.facts` から読んで適用する。
- 適応出題は `selectAdaptiveAdditionFact` で、既存の未マスター優先、にがて優先、2連続ミス時の易化重みを流用する。
- にがて記録は既存の `progress.facts` に保存する。たしざんは `operation: 'addition'` と `areaId` を持ち、九九と区別する。
- B1では、たしざんのにがて克服を新モンスター、なかま、図鑑報酬には接続しない。九九モンスター報酬は従来どおり九九IDだけを対象にする。
- ボス解放の段別正解数は、九九IDだけを集計し、たしざんの `left` 値を段として扱わない。

## SaveData

# 25.33 Phase 16 学習整合性・4星共通の復習・探検の土台

この節は既存の称号保存、復習、ミッション、ベスト記録に関する記述より優先する。新しい星や報酬の大量追加ではなく、既存4星を同じ品質で遊べるようにする。

## 学習記録と適応

- `facts` に `firstIncorrectAt` と `overcomeAt` を追加する。克服の条件は累計3正解以上と、最初の誤答より後の日の正解。直近8件から誤答が消えても判定根拠を失わない。
- 克服済みの収集実績は再度間違えても取り消さない。最近の誤答は適応選択と次の復習には引き続き反映する。
- 「にがて」は実際の誤答があり、未克服の式に限定する。遅かっただけの式をモンスター扱いしない。復習待ちの式は別に選択できる。
- 学習中の未保存の解答も次の適応選択に反映する。問題の難度は生成ルールから導出し、習熟度で置き換えない。保存済み式は選択エリアの生成条件を再検証する。
- 2連続ミス後は同じエリア内の易しい難度から出題する。3桁エリアでも空の易問集合を選ばない。

## 星別の復習・ミッション・記録

- `/review?planet=add|subtract|divide|multiply` で同じ復習ループを使う。わり算の商とあまりの4択も既存判定を流用する。
- 各星で「10問正解」「おすすめエリアで5問」「5問連続」の3ミッションを用意する。表示と進捗は演算・エリア/段で絞る。連続正解は1プレイ内の実際の最大連続数で、複数プレイを足さない。
- 記録キーは星、モード、難易度、エリア/段、制限時間、解答方式、練習の問題数を含む。ロケットのランダムな出題内訳はミックスとして固定し、ボス記録はボスIDと難易度で分ける。
- 条件の分からない旧ベストは `legacy:`、旧履歴は `planet:'legacy'` で保全し、新記録と比較しない。既存ロケット距離も保全する。

## 称号の安定ID

- `player.titles`、`player.currentTitle`、称号の `collectionRecords` は表示名でなく、`rule:` / `boss:` / `master:` の安定IDで保存する。表示・図鑑・カスタムではIDから名称を解決する。
- 称号を取得しても装備中の称号は変えない。カスタムと設定で明示的に選び替える。
- 「かけざんビギナー」「くくファイター」は九九の解答からのみ取得する。演算共通の初回・連続正解称号は `origin:'all'` とする。
- 重複していたひき算大きい数ボスの通常称号は「おおひきこまんだー」に分離する。旧名称の復元先はボス撃破記録で判断し、両方撃破済みなら両方の称号を保持する。

## ヒントと練習設定

- たし算のダミーは桁数に合う候補に限定する。1桁問題には±100や不自然な桁の逆順を混ぜず、繰り上がり忘れ・±10・±1を使う。

- おぼえる・復習に明示的な「ひんと」ボタンを置く。ネイティブdialogの中央モーダルに、位ごとの繰り上がり、波及的な繰り下がり、等分とあまりの関係を表示する。プレイ領域や4択を押し広げない。
- 解答結果にヒント利用を残し、履歴に利用数を保存する。今回は報酬・マスター条件を変更せず、翌日の独力定着の評価は次フェーズとする。
- 先生コード内に「じっくり（5問・4択）」「いつもの（9問・4択）」「ちゃれんじ（15問・入力）」と個別設定を置く。加減算の整数入力を有効にし、わり算・円周率は4択を維持する。
- 静かな設定は音声・効果音を切り、背景の動きを減らす。時間バジェットはプリセットで変更しない。適応選択を有効にする。
- 解答フィードバック中の数字入力、空入力の確定、ヒント表示中のキーボード解答を防ぐ。
- 開始前の選択領域はグリッドの確保高に合わせて伸ばし、内部だけをスクロールする。タイトル・解答方式・開始ボタンを重ねない。
