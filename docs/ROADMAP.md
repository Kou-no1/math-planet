# けいさんのほしの発展方針

## 今回の到達範囲：Phase 16

- 克服状態の永続化、問題難易度と習熟度の分離。
- 星・対象エリア・難易度・時間・解答方式・問題数別の記録。
- 固定IDの称号と、取得済みデータのv15移行。
- 4星共通の復習と星別の今日のめあて。
- 位の計算・まとまり・配り方を確かめるヒント。
- 練習の問題数・解答方式のプリセットと静かに遊ぶ設定。
- 花壇・補給庫・リングの灯り・配送港のおてつだいと進捗表示。

## 次の段階：技能を確かめる

- 式の正答数と、技能の定着を区別する。くりあがり・波及するくりさがり・あまりなどを集約する。
- ヒントなしの翌日正答を確認し、初見の式への転移も評価する。
- 先生向けのローカル学習レポートを追加する。必要な場合だけJSONを共有し、児童の行動を無断で外部送信しない。
- 苦手だった技能への短い復習と、理解を確かめる問題を提示する。
- 0を明示的に学ぶ入門は別エリアとして仕様を確定する。既存ひきざんエリアの生成条件は変更せず、負の答えを出さない。

## 世界観を育てる

- 計算の意味に沿った依頼を追加する。たしざんは増やす、ひきざんは残りや差を調べる、かけざんは同じまとまり、わりざんは等しく配る。
- ボスを星の管理者や試練の相手として描く。誤答を罰とせず、一緒に整理する演出を用意する。
- 正解回数による進捗の見た目と、技能の定着による変化を区別する。
- 毎日ログインしないことによる退化・仲間の喪失・罰則は設けない。
- 装備は共通のくくっち号に反映し、お気に入りコーデ保存を検討する。

## 新しい星と学校利用

- 小数は計量・整備、分数は分け合う工房を舞台に、量の視覚化から導入する。
- 小数は固定小数または十進の表現、分数は既約分数による厳密な判定を先に設計する。
- 4星のミックスは前提技能が揃った後の任意チャレンジにする。
- オフライン・更新時のセーブ保護を優先し、PWA、複数プロフィール、クラウド保存は個別フェーズで設計する。
- AI会話、無制限の物語生成、全体ランキングは現段階では追加しない。

## 品質の基準

- 新しい星は生成・判定・報酬・復習・タグ・バックアップ・フルオープンをセットで検証する。
- 320×568、390×844、768×1024、1366×768で選択肢・ヒント・設定を検証する。
- 実プレイデータを確認するまでは、8割正答の維持や学習効果の向上を保証しない。
- 技能別の翌日正答、ヒント利用、途中離脱を評価する。コイン総数や順位だけで評価しない。

## ブラウザ検証

`scripts/verify-learning.mjs` はPlaywrightを利用する。開発サーバーを起動して実行する。

```powershell
$env:PLAYWRIGHT_MODULE = 'Playwrightパッケージのパス'
$env:QA_BASE_URL = 'http://127.0.0.1:5176/math-planet/'
node scripts/verify-learning.mjs
```

既定ではEdgeのヘッドレス環境を使う。`QA_BROWSER_CHANNEL`、`QA_OUTPUT_DIR` で変更できる。画像と検証結果は既定で一時ディレクトリの `kukucchi-phase16` に保存する。
